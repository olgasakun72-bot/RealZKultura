[ КОНФИГУРАЦИЯ ] // КАНАЛ СВЯЗИ С МОДЕЛЬЮ

+---HF TOKEN---+ runtime override

Токен зашит в код константой HF_TOKEN. Для локальной отладки его можно переопределить здесь — значение сохранится только в вашем браузере (localStorage) и никуда не отправляется, кроме самого запроса к Hugging Face.

[СТАТУС]: используется значение из исходного кода (заглушка).

+---SECURITY NOTICE---+

Не публикуйте реальный токен в клиентском коде. Любой посетитель страницы увидит его в исходнике и сможет израсходовать вашу квоту. Правильная схема для продакшена:

  1. Клиент шлёт запрос на свой прокси (Cloudflare Worker, Vercel/Netlify Function, Deno Deploy) — без токена в URL и в теле.
  2. Прокси добавляет заголовок Authorization, ограничивает origin, частоту (rate limit) и длину запроса.
  3. Токен живёт в переменной окружения сервера, а не в репозитории.
  4. В .gitignore — .env, в истории коммитов — проверка секретов (gitleaks / trufflehog).

Дополнительно: браузерный вызов api-inference.huggingface.co может быть отклонён CORS — это ожидаемо. В таком случае терминал автоматически переходит в OFFLINE-режим и отвечает локальным движком, сохраняя формат протокола.
