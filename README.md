# [0XTRACE] // ZeroTrace Academy

Приватный учебный портал по **OSINT**, **кибербезопасности** и **социальной инженерии**.
Чистый статический сайт: HTML5 + CSS3 + Vanilla JS, без фреймворков, без сборки, без бэкенда.
Готов к выкладке на GitHub Pages «как есть».

```
    ___     \    \  ______     _____      ___       _____    ______
   / \ \     \\  /\   \____\    |  __ \    / \ \     / ____\  |  ____\
  | | | |     \\        __     | |\) |   |  _  |   | |       |  |__
  | |_| |     \/\       __     |  _  /   | | | |   | |___    |  ___\
    \___/   \    \     __     |_| \_\   |_| |_|    \____|   |______\
```

Навигация сквозная для всех шести страниц:
`[ГЛАВНАЯ] [КЕЙСЫ] [ГРАФ] [АРСЕНАЛ] [ЛАБОРАТОРИЯ] [CORE_KERNEL]`.

1. библиотека графа `cytoscape@3.34.4` с jsDelivr/unpkg — **только на `network.html`**,
   с фиксированной версией и контролем целостности SRI; при недоступности CDN страница
   переходит на встроенный canvas-рендерер `CORE_RENDERER` (см. ниже);
2. запрос к `api-inference.huggingface.co` — **только на `assistant.html`** и только если задан токен.

Все остальные страницы работают полностью автономно.

## Локальный запуск

Сайт работает при обычном открытии файлов в браузере:

```bash
# вариант 1 — просто открыть
open index.html            # macOS
xdg-open index.html        # Linux

# вариант 2 — локальный сервер (рекомендуется: корректные относительные пути)
python3 -m http.server 8080
# затем http://localhost:8080/
```

Установка зависимостей не требуется. Без сети `network.html` отрисует тот же граф
собственным рендерером, `tools.html` и остальные страницы не меняются вовсе.

## Деплой на GitHub Pages

### Способ A — через GitHub Actions (в репозитории уже настроен)

1. Откройте **Settings → Pages → Build and deployment**.
2. В поле **Source** выберите **GitHub Actions**.
3. Запушьте ветку `main` — workflow `.github/workflows/pages.yml` опубликует сайт автоматически.
4. Адрес появится в Settings → Pages, обычно `https://<username>.github.io/<repo>/`.

### Способ B — публикация ветки без Actions

1. **Settings → Pages → Source** = `Deploy from a branch`.
2. Branch: `main`, каталог: `/ (root)`.
3. Сохранить. Сайт будет доступен через 1–2 минуты.

Сайт лежит в корне репозитория и использует только относительные ссылки, поэтому работает
и в корне домена, и в подкаталоге проекта (`/<repo>/`) без правок.

## Граф связей (`network.html`)

Двухпанельная рабочая область: **70 %** — интерактивный граф, **30 %** — «Консоль
тактического анализа». Ниже 1100 px панели складываются в колонку.

**Классы узлов и жёсткая цветовая схема:**

| Класс | Цвет | Что содержит |
|-------|------|--------------|
| `nick` | `#ffb000` (янтарь) | никнеймы, аккаунты, handle'ы |
| `contact` | `#33ff33` (фосфор) | e-mail, телефоны, мессенджеры |
| `identity` | `#ff3333` (красный) | ФИО, документы, персональные классы |
| `geo` | `#0066ff` (синий) | координаты, IP, ASN, часовой пояс, регион |

В базе 16 узлов (`n01`…`n16`) и 21 связь (`e01`…`e21`); вес связи — `HARD`, `SOFT` или
`CLOSED`. Все значения синтетические: телефоны и почта маскированы, координаты указывают
на точку в центре Москвы, а узел `n16` закрыт регламентом `[REDACTED]`.

**Что делает консоль:**

* клик по узлу — `trace_route()` считает кратчайший маршрут от первичной улики `n01`
  (ненаправленный BFS), подсвечивает всю цепочку на графе и печатает досье:

  ```
  [SELECT]: n09 // kind=контактные данные // platform=профиль
  [VALUE]: +7 9** ***-41-02 (маскирован)
  [STATUS]: EXTRACTED // [METHOD]: Messenger Parsing // [GEO]: RU/BY. Связан с Telegram @wizard_dev.
  [LINKS]: 2 (1 in / 1 out) -> n07, n02
  [ROUTE]: n01 -> n07 -> n09 // hops=2 // soft=2 (транзитивная ошибка, выводом не является)
  [VERDICT]: уровень уверенности НИЗКАЯ. Маршрут подсвечен на графе.
  ```

  Узлы класса `CLOSED` дополнительно получают строку `[DEFENSIVE_ONLY]`;
* `[ RUN TRACE SIMULATION ]` — сборка цепочки с нуля: граф очищается, затем с паузой
  **1 секунда на шаг** последовательно появляются `Никнейм → Email → Телефон → Telegram →
  Геолокация → ФИО`, а журнал печатается параллельно машинкой и завершается вердиктом
  `FLAG{ALEX_GATES}`;
* `[ ПОЛНЫЙ ГРАФ ]` — возврат ко всем 16 узлам; `[ ДАМП ТАБЛИЦЫ СВЯЗЕЙ ]` — выгрузка матрицы
  в журнал; `[ ОЧИСТИТЬ ЖУРНАЛ ]`, `Esc` — сброс выделения;
* горячие клавиши: `T` (русская `Е`) — симуляция, `F` (русская `А`) — полный граф.

**Движок и отказоустойчивость.** Порядок подключения: локально заданный `window.cytoscape` →
`cdn.jsdelivr.net` → `unpkg.com` → встроенный `CORE_RENDERER`. Версия пакета зафиксирована
(`3.34.4`), у обоих источников проставлен `integrity` (SRI `sha384-…`) и `crossorigin="anonymous"`,
таймаут ожидания — 7 с. Индикатор в шапке показывает фактический режим: `LOCAL`, `CDN` или `CORE`.

Свечение узлов и бегущие импульсы по связям рисуются отдельным слоем `LightLayer`
(`globalCompositeOperation = 'lighter'`) поверх полотна библиотеки: у Cytoscape.js нет
свойств тени, поэтому подсветка реализована собственным оверлеем — он же используется
встроенным рендерером, так что визуально оба режима неразличимы. Под графом есть
статическая матрица связей `#link-matrix` — она работает и без JavaScript.

## Арсенал утилит (`tools.html`)

27 записей в пяти категориях, включая обязательный набор: **Sherlock, Maigret, WhatsMyName,
ExifTool, Metadata2Go, Have I Been Pwned, Intel X, Nmap, Wireshark, OWASP ZAP, SET, Gophish**.

| Категория | Записей | Примеры |
|-----------|---------|---------|
| Разведка по никнеймам | 5 | Sherlock, Maigret, WhatsMyName, holehe, Wayback Machine |
| Анализ метаданных | 6 | ExifTool, Metadata2Go, strings, jhead, SunCalc, FotoForensics |
| Мониторинг утечек | 4 | Have I Been Pwned, Intel X, trufflehog, gitleaks |
| Сетевой аудит | 8 | Nmap, Masscan, Wireshark, tshark, testssl.sh, Nikto, OWASP ZAP, crt.sh |
| Симуляторы атак | 4 | SET, Gophish, OWASP Juice Shop, DVWA |

Каждая запись несёт: название, тип (`CLI` / `Web` / `GUI` / `Docker`), порог входа
(`Новичок` / `Профи`), принцип работы, реальную базовую команду, правовую отметку и ссылку.
Команда копируется кликом — через `navigator.clipboard` с запасным путём через
`textarea` + `execCommand`, отклик `[СКОПИРОВАНО В БУФЕР]`.

Поиск мгновенный и морфологически устойчивый: запрос нормализуется (`ё → е`, регистр),
разбивается на слова, у каждого отсекается падежное окончание, поэтому «метаданные» находит
«метаданных», а «инъекц» — «инъекций». Несколько слов работают как логическое И.
Дополнительно фильтры по категории, типу и порогу входа, два вида — карточки и ASCII-таблица,
счётчик выдачи `[ВЫДАЧА]: найдено N из 27`, клавиша `/` — фокус на поиск, `Esc` — сброс.

**Правовые отметки** — обязательная часть карточки, а не украшение:
`ТРЕБУЕТ РАЗРЕШЕНИЯ` (8 записей: сканирование чужих сетей, сниффинг, фишинг-симуляции),
`ТОЛЬКО СВОИ ДАННЫЕ` (8 записей: метаданные и аккаунты), `УЧЕБНЫЙ СТЕНД` (2 записи),
`БЕЗ ОГРАНИЧЕНИЙ` (9 записей). Примеры команд используют документированные диапазоны
RFC 5737 (`192.0.2.0/24`) и домен `example.com`, чтобы их нельзя было применить к живым целям.

## Подключение внешнего узла (`assistant.html`)

По умолчанию в коде стоит заглушка:

```js
const HF_TOKEN = "ЗАМЕНИ_НА_СВОЙ_ТОКЕН_HUGGING_FACE";
```

Модель и эндпоинт:

```js
const HF_MODEL    = "meta-llama/Meta-Llama-3-8B-Instruct";
const HF_ENDPOINT = "https://api-inference.huggingface.co/models/" + HF_MODEL + "/v1/chat/completions";
```

Запрос формируется как массив `messages`, где **первым элементом всегда идёт жёсткий
системный промпт** `SYSTEM_PROMPT` (роль `system`), затем хвост истории и сообщение пользователя.
Входная точка — `kernel_exec()`, ответ нормализуется `normalize_response()`, при недоступности
внешнего узла работает `core_kernel_reply()` по локальной базе `CORE_KB`.

### Где взять токен

1. Зарегистрируйтесь на [huggingface.co](https://huggingface.co).
2. **Settings → Access Tokens → New token** (тип `Read` достаточно).
3. Модель `meta-llama/Meta-Llama-3-8B-Instruct` — **gated**: откройте страницу модели
   и примите лицензионное соглашение, иначе API вернёт `401/403`.

### Как задать токен

* **Локально, без правки кода** — на странице `assistant.html` есть блок `[ КОНФИГУРАЦИЯ ]`:
  вставьте токен и нажмите `[ СОХРАНИТЬ ]`. Значение попадёт в `localStorage` вашего браузера
  и никуда больше. Кнопка `[ ПРОВЕРИТЬ КАНАЛ ]` делает тестовый запрос.
* **В коде** — замените значение константы `HF_TOKEN`.

> ### ⚠️ Безопасность: не публикуйте реальный токен в клиентском коде
> Любой посетитель страницы увидит его в исходнике через DevTools и сможет израсходовать
> вашу квоту или получить доступ к вашему аккаунту HF (в зависимости прав токена).
>
> Правильная схема для публичного сайта:
> 1. Клиент обращается к **вашему** прокси — Cloudflare Worker, Vercel/Netlify Function, Deno Deploy.
> 2. Прокси добавляет `Authorization: Bearer <HF_TOKEN>`, проверяет `Origin`, ограничивает
>    частоту запросов (rate limit) и длину сообщения.
> 3. Токен хранится в **секрете/переменной окружения** сервера, а не в репозитории.
> 4. `.env` внесён в `.gitignore` (уже сделано), история коммитов проверяется `gitleaks`/`trufflehog`.
>
> Если токен всё же попал в публичное дерево — немедленно отзовите его в HF и выпустите новый.

### Если узел недоступен

Браузерный вызов `api-inference.huggingface.co` может быть отклонён по CORS, модель может
оказаться «холодной» (`503`) или квота исчерпанной (`429`). В этом случае терминал печатает
обрыв канала в формате аварийного сообщения Linux-терминала:

```
[CRITICAL]: Connection to 0xBASE node lost. Check local routing tables or SSH keys.
[TRACE]: <причина: статус, таймаут, CORS>
[FALLBACK]: переключаюсь на локальное ядро CORE_KERNEL. Формат протокола сохранён.
```

Индикатор состояния переходит в `NODE LOST`, после чего:

1. запрос обрабатывает локальное детерминированное ядро с базой знаний по девяти темам
   (никнейм-разведка, метаданные, SQL/OWASP, фишинг, GEOINT, аудит, флаги, пароли, справка о ядре);
2. формат протокола сохраняется: ответы идут с префиксами `[PROCESS]:`, `[COMMAND]:`, `[HINT]:`.

Таким образом страница остаётся рабочей и демонстрационной даже без токена и без сети.

## Протокол DEFENSIVE_ONLY

Системная инструкция ядра `0xBASE` запрещает вежливые шаблонные ответы и требует начинать ответ
с технической сути. Пункт 3 инструкции блокирует запросы на боевой эксплойт, рабочий фишинг
и атаку на реального человека:

```
КРИТИЧЕСКАЯ ОШИБКА: Запрос нарушает протокол DEFENSIVE_ONLY. Действие заблокировано.
```

Такая же проверка продублирована **на клиенте** (`FORBIDDEN_PATTERNS`): даже если внешний узел
ответит иначе, запрос наступательной категории получит блокировку и оборонительный разбор.
Тот же регламент действует на графе: узлы класса `CLOSED` не раскрывают значений.

Три ограничения проекта, зафиксированные в манифесте на `index.html`:

1. **Письменное разрешение** на любую проверку чужой системы.
2. **Минимально достаточные данные** — досье на живого человека не является результатом работы.
3. **Оборонительный результат** — ценность отчёта в закрытых, а не в найденных дырах.

Все персонажи кейсов вымышлены, все стенды локальны, флаги проверяются в браузере посетителя.

## Флаги учебных дел

Формат: `FLAG{...}`. Проверка нормализует регистр, пробелы и допускает ввод значения
без обёртки `FLAG{}`. Флаги намеренно не публикуются в README — ценность представляет
ход расследования, а не строка ответа.

| Дело | Класс | Сложность | Где ответ |
|------|-------|-----------|-----------|
| `CASE-001` «Исчезнувший эдвайзер» | nickname resolution | средний | блок «ДАМП УЛИК», пересечение двух независимых источников |
| `CASE-002` «Инсайдерский слив» | file forensics / metadata | высокий | вывод `exiftool -a -u -G1`, поле XMP Author |
| `CASE-003` «Геолокация по отражению» | GEOINT / chronolocation | экспертный | наблюдения OBS-07…OBS-09 и обратная задача SunCalc |
| Лаборатория | A03:2021 Injection | базовый | payload `' OR '1'='1` в поле логина или пароля |
| Граф связей | link analysis | средний | `[ RUN TRACE SIMULATION ]` на `network.html`, вердикт по узлу `n15` |

Прогресс по архиву дел хранится в `localStorage` (`zt_cases_state_v1`), статистика лаборатории —
в `zt_lab_stats_v1`, токен внешнего узла — в `zt_hf_token_v1`. Сброс — кнопкой
`[ СБРОСИТЬ ПРОГРЕСС ]` на соответствующей странице.

## Проверка

Страницы проверены на: синтаксис всех встроенных скриптов, баланс HTML-тегов и уникальность `id`,
соответствие identifiers/лексикона внутреннему регламенту проекта, работу графа на обоих движках
(внешняя библиотека и встроенный canvas), симуляцию трассировки и формат досье, поиск и фильтры
арсенала, копирование команд, бут-последовательности, валидацию флагов, детектор инъекций и
сетевой контракт ядра `0xBASE` (состав `messages`, заголовки, поведение при обрыве канала).
